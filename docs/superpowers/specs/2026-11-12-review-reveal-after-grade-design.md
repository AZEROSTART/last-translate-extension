# 复习卡「先评级、再揭晓、可改判」设计

- 日期：2026-11-12
- 状态：已实现（2026-11-13）
- 相关：`2026-11-12-learning-loop-design.md` §5.2（本文修订其中复习卡的交互顺序）
- 范围：只改侧栏复习卡的交互与提交时机；不动 SRS 间隔表、学习库 schema、悬停卡片

## 1. 问题

现在点完「忘了 / 模糊 / 认识」，卡片立刻换成下一张，**这张词的释义从头到尾不会出现**：

- `src/panel/review.ts:548-553`：`submit()` 成功后就 `state.queue.shift()`，只重渲染下一张。
- 只有事先点「想不起来，看答案」（`renderAnswer`，`review.ts:244`）才看得到释义。
- 四选一答对时同样直接出队（`review.ts:586-595`），也看不到释义。

结果：用户评完级但无法确认自己是否答对；「认识」变成在无反馈下按下的按钮。

## 2. 目标与非目标

### 目标

1. 点任一评级后，卡片**原地展开**答案：主语言释义、其他已存语言并列、完整原句。
2. 展开后仍可**改判**；只有最终选择写入学习库，且只写一次。
3. 每张卡都以「下一张」收尾；自评卡与四选一卡走同一个提交点。
4. 学习目标是「英文 + 日语」这类多语言时，答案区同时显示日语释义。

### 非目标

- 不改 `applyGrade` / `INTERVALS_MS` / box 语义。
- 不做反向卡、拼写题（另议）。
- 不改悬停卡片「只显示目标语言」的规则。
- 不新增学习库字段，不改 `review-answer` 消息结构。

## 3. 交互状态机

每张卡有两个可见状态：

```
idle
┌──────────────────────────────┐
│ outlive  v.  英语             │
│ Small tools often ____ their  │
│ larger competitors.           │
│                              │
│ [ 想不起来，看答案 ]           │
│ [ 忘了 ] [ 模糊 ] [ 认识 ]     │
└──────────────────────────────┘
        │ 点任一档
        ▼
graded
┌──────────────────────────────┐
│ outlive  v.  英语             │
│ Small tools often ____ their  │
│ larger competitors.           │
│                              │
│ 比……存在得更久                 │
│ 日语 · より長く生き残る         │
│ Small tools often outlive …   │
│                              │
│ [ 忘了 ] [ 模糊 ] [ 认识 ]✓   │
│              [ 下一张 ]        │
└──────────────────────────────┘
```

- **idle → graded**：点三档中任意一个。评级只是**选择**，不写库。
- **graded 内改判**：再点另一档，只换高亮，不写库。
- **graded → 下一张**：发一次 `review-answer`，`grade` = 当前选择。
- **看答案**（idle 时的「想不起来，看答案」）只展开答案，不进入 graded，也不改选择；展开后仍要点一档。
- 提交成功后：`answered += 1`、`grade === "good"` 时 `correct += 1`、出队、清空选择。

## 4. 提交时机

- 写库发生在「下一张」，不是点评级时。
- 一次复习**恰好一次** `review-answer`，避免「先写 good 再改成 again」导致 `applyGrade` 二次叠加。
- 写库失败：留在 graded，选择保留，按钮恢复可点，可再点「下一张」重试；不推进队列。
- 点「✕ 结束」时若处于 graded：先按当前选择提交（best effort），再显示结束页；提交失败也结束，词仍到期，下次会再出现。
- 面板关闭 / 页面导航时未提交：本次不记账，词仍到期。这是 fail-closed，不丢学习历史。

## 5. 四选一

- 点选项即评级：答对 → `good`，答错 → `again`。
- 立即进入 graded：标出对/错选项、显示正确答案、展开答案区、显示「下一张」。
- 四选一是证据题，**不可改判**：graded 状态下隐藏三档按钮，只留「下一张」。
- 作答后把题目对象**冻结**在面板状态里：即使随后切换「答案语言」，选项、对错高亮与正确答案也保持作答时的那一道；冻结题无法重建时也不回落到三档自评。
- 答对也停在 graded，不再直接出队（这是与现状的行为差异，见 §1）。

## 6. 多语言答案区

复用 `renderAnswer()` 现有拼装（`review.ts:258-283`）：

- 主行：`state.glossLang || word.glossLang` 的释义。
- 次行：其余 `glosses`，格式 `语言 · 释义`，浅色并列。
- 主语言释义缺失：占位「X 释义尚未生成」，不阻塞提交。
- 完整原句：`contexts.at(-1).sentence`，没有语境时回退到 `surface`。

额外的语言释义来自收录时的 `learningLangs`；本文不新增取词逻辑。

## 7. 与存储刷新共存

`chrome.storage.onChanged`（`src/panel/main.ts:578-596`）与切换 tab（`showView`）都会调 `review.refresh()`，最终进 `load()`。`load()` 现在会重建队列并把 `revealed` 复位，会把结果卡吞掉。

规则：

- `load()` 在 `state.pending !== null`（已评级、未提交）时直接返回并置 `pendingReload = true`，**不重建队列、不重置 revealed / pending、不重渲染**；这次刷新在「下一张」提交后补跑。代价是筛选 chip 的计数在结果卡期间可能落后一个词。
- 提交成功后清空 pending，再走一次 `refresh()` 用存储里的最新状态重建队列。
- `buildSpotQuestion` 使用的 `state.all.words` 在此期间可能少一个刚提交的词，不影响当前卡（题目已生成）。

## 8. 可达性与视觉

- 选中的档位用既有 `.is-active` / `aria-pressed="true"` 表达；改判时同步更新。
- 答案区沿用 `.ilmt-review-answer` 样式，展开后容器加 `aria-live="polite"`，读屏能播报释义。
- 「下一张」复用 `.ilmt-review-next` 样式（现有四选一答错路径已在用）。
- 提交中三档与「下一张」都 disabled，沿用 `state.busy`。

## 9. 测试

单测（`tests/unit/panel-review.test.ts`，现有 fake deps）：

1. 点「认识」后答案出现、仍停留在同一张、进度数字不变。
2. 点「认识」再点「模糊」：高亮切换，`answer` 未被调用。
3. 「下一张」只调用一次 `answer`，`grade` 为最终选择，随后显示下一张。
4. 多语言：答案主行是主语言，次行包含另一语言。
5. 四选一答对：显示答案 + 「下一张」，写库一次、`grade=good`。
6. 四选一答错：显示正确答案 + 答案区，写库一次、`grade=again`。
7. graded 期间调用 `refresh()`：仍是同一张、答案仍展开。
8. graded 时点「结束」：先提交当前选择，再显示结束页。
9. `answer` 失败：停在本卡，选择保留，不推进。
10. idle 时点「看答案」：只展开答案，不出现「下一张」，三档仍可点。

E2E：沿用 `tests/e2e/learning.spec.ts` 的收录 + 复习路径，断言点「认识」后出现释义文本，再点「下一张」后徽标/待复习数更新。

## 10. 风险与取舍

- **每张卡多一次点击**：复习节奏会慢一点。收益是看得见答案，且改判让评级更诚实。
- **延迟写入**：用户在 graded 状态关掉面板会丢一次记账。词仍到期，属于安全方向。
- **改判空间**：允许从「认识」降到「模糊」，但不提供「无限回退已经提交的卡」——提交即定稿。
- **不做**：把三档换成二选一、按作答时长自动判档、反向卡。留待后续评估。
