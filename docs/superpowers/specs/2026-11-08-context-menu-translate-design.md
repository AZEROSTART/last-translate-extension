# 右键菜单「翻译当前页面」· 设计文档

- 日期：2026-11-08
- 状态：待批准
- 范围：只新增一个右键菜单入口，不改动现有翻译、侧栏聊天和快捷键逻辑

---

## 1. 意图

`Alt+A` 快捷键在用户环境里没有触发翻译。用户需要一个**不依赖快捷键**、点一下就能翻译当前网页的入口。用户已选定：把入口放在**网页右键菜单**。

## 2. 用户流程

1. 用户在任意网页上右键。
2. 菜单里出现「翻译当前页面」。
3. 点击后，当前标签页开始翻译，行为和 `Alt+A` 完全一致：
   - 页面顶部出现现有的「翻译已开启」提示；
   - 非中文段落下方插入中文译文；
   - 已翻译过再点一次不会重复翻译（沿用 `translatePage` 的幂等保护）；
   - 没有配置模型时，显示现有的错误提示。

## 3. 实现方案

### 3.1 注册菜单

在 `src/background/index.ts` 中：

- 监听 `chrome.runtime.onInstalled`，先 `chrome.contextMenus.removeAll()`，再创建菜单项：
  - `id: "translate-page"`
  - `title: "翻译当前页面"`
  - `contexts: ["page"]`
- 使用 `onInstalled` 而不是顶层创建，避免 service worker 每次启动重复注册同一个 id。
- 创建失败只吞掉，不影响后台其他功能。

### 3.2 处理点击

监听 `chrome.contextMenus.onClicked`：

- 只处理 `info.menuItemId === "translate-page"`；
- 调用现有的 `sendToCommandTab(tab, { type: "activate" })`，复用 `Alt+A` 的命令链路；
- 不新增消息类型、不改内容脚本、不改 manifest 权限（`contextMenus` 权限已经存在）。

## 4. 非目标

- 不加侧栏按钮；
- 不加「还原页面」菜单项；
- 不改 `Alt+A` 的绑定或快捷键诊断；
- 不改翻译请求、队列、渲染逻辑。

## 5. 边界与失败处理

- 右键菜单不会出现在 `chrome://` 等受保护页面；这是 Chrome 的行为，不做额外处理。
- 页面没有内容脚本（例如扩展刚更新但页面未刷新）时，沿用现有 `sendToCommandTab` 的静默失败，不弹额外错误。
- 菜单注册失败不阻塞扩展启动；用户仍可使用 `Alt+A` 或侧栏。

## 6. 验收标准

1. 在普通网页右键，能看到「翻译当前页面」。
2. 点击后页面顶部出现翻译横幅，段落开始出现中文译文。
3. 再次点击不会重复插入译文。
4. 未配置模型时显示现有的中文错误提示，而不是静默无反应。
5. 单元测试覆盖：菜单注册、点击后发送 `{ type: "activate" }`、忽略其他菜单 id。
6. 现有测试、`npx tsc --noEmit`、`npm run build` 全部通过。
